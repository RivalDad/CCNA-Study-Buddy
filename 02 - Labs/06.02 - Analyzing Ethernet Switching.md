# Lab 06.02 — Analyzing Ethernet Switching

[[01 - Lessons/06 - Ethernet LAN Switching Part 2 and ARP|← Parent lesson]] · [[03 - MOCs/Labs MOC|Labs MOC]] · [[00 - CCNA Home|CCNA Home]]


## Purpose

Predict what happens when a ping starts with empty ARP/MAC tables, then verify your prediction.

## Expected Sequence

```text
1. ARP Request — broadcast
2. Switch learns requester's source MAC
3. ARP Reply — unicast
4. Switch learns responder's source MAC
5. ICMP Echo Request
6. ICMP Echo Reply
```

## Commands

```cisco
show mac address-table
clear mac address-table dynamic
show arp
```

Host:

```text
arp -a
```

## Lab Questions

- Which frame causes the switch to learn each MAC?
- Why is the first ARP request flooded?
- After learning, which frames become unicast-forwarded?
- What changes after clearing the MAC table and repeating the ping?
